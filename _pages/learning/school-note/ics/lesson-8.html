第三章 第八讲：联合体、地址空间与缓冲区溢出

来源：ICS08，2026 年 10 月 8 日，53 页；配合 Attack Lab 实验讲义。

1. 联合体与位模式

联合体各成员从同一地址开始，大小是容纳最大成员并满足整体对齐所需的字节数。课件中的 char、int[2]、double 联合体为 8 字节，对应结构体为 24 字节。

把浮点位模式解释成整数，与数值类型转换是两种运算：浮点数 1.0 的单精度位模式为 0x3f800000，而把 1.0 转成整数得到 1。位模式分析用于解释编码；数值转换按目标类型重新编码。

小端序将最低有效字节放在最低地址。连续字节 f0 f1 f2 f3 f4 f5 f6 f7 在 x86-64 中解释为 64 位整数 0xf7f6f5f4f3f2f1f0。

2. 进程地址空间

  • 代码段：机器指令；只读常量通常置于只读数据区域。
  • 静态数据区：全局变量、静态变量，生命周期贯穿程序运行。
  • 堆：动态分配对象，由分配与释放操作控制生命周期。
  • 栈：活动调用的栈帧，保存局部数据、返回地址和寄存器。
  • 共享库及大块映射区：通过映射组织，位置与具体进程布局有关。

地址空间图描述虚拟地址，不能直接当作物理内存布局。递归每层都保留独立栈帧；大局部数组使每层消耗增大。课件中每层约 128 KiB 的数组很快耗尽栈空间。

3. 越界写怎样改变程序状态

C 中数组访问转成地址计算与内存读写，机器指令不记录源代码中的数组边界。结构体中数组越界可能覆盖相邻浮点字段；栈缓冲区越界可能覆盖保存的寄存器或返回地址。

课件 echo 分配 24 字节栈空间，缓冲区从 %rsp 开始，返回地址在偏移 24 处。即使源代码数组仅 4 字节，返回地址偏移仍由实际栈帧确定。输入 24 个普通字符后，字符串终止符写入偏移 24，已经改动返回地址最低字节。

分析顺序：确定缓冲区首址，计算目标字段相对偏移，按小端序解释覆盖后的字节，再跟踪 ret 的取址与跳转。

4. 代码注入与 ROP 的区别

代码注入把指令字节放入输入缓冲区，并把控制流转到该缓冲区。ROP 将返回地址组织成已有指令片段的地址序列；每个片段通常以 ret 结束，栈同时存放后续片段地址与所需数据。

ret 的效果是从栈顶取新 PC，再令 %rsp 增加 8；popq 还会额外消耗一个栈槽。手工追踪 ROP 时，要逐条记录寄存器和 %rsp，区分地址与该地址中的值。

5. 课件中的保护机制

机制作用
长度受限的输入将实际读入长度限制在缓冲区容量内，并保留终止符空间
地址随机化使栈及映射区域的地址随运行变化
不可执行栈阻止把栈中的数据直接作为指令执行
栈金丝雀在返回前比较栈中的检测值，发现覆盖后终止执行

这些机制分别作用于输入、地址预测、执行权限和覆盖检测。ROP 使用已有可执行代码，因此不可执行栈本身不阻止 ROP；栈金丝雀仍可能检测到覆盖。

fgets(buf, n, stdin) 最多存入 个字符并写终止符；strncpy 在源串过长时可能不写终止符，使用时需要明确长度语义。

6. 课堂例题：联合与结构的存储比较

ICS08 第 3—10 页。 char c; int i[2]; double v; 作为结构体时偏移为 0、4、16，总大小 24；作为联合时各成员都从偏移 0 开始，最大成员占 8 字节、对齐要求 8，因此联合总大小为 8。

联合 float f; unsigned u; 的两个成员共享同一组 32 位。先写 u=0x3f800000 再按 float 位模式解释，得到 1.0；直接把整数 0x3f800000 数值转换为 float 则得到约 。位模式重解释与数值转换执行的是不同操作。

6.1. 同一组字节的大小端读取

给 8 个字节依次写 f0 f1 f2 f3 f4 f5 f6 f7。x86-64 小端时：

视图读出的十六进制值
unsigned char[8]f0,f1,f2,f3,f4,f5,f6,f7
unsigned short[4]f1f0,f3f2,f5f4,f7f6
unsigned int[2]f3f2f1f0,f7f6f5f4
unsigned long[1]f7f6f5f4f3f2f1f0

大端读取则各多字节值按字节出现顺序写为 f0f1、f2f3，或 f0f1f2f3。课件对比 IA32 与 x86-64 时还改变了 long 的宽度，因此先确认成员宽度，再判断字节序。

7. 课堂例题：实际对象放在哪个区域

第 14—16 页。 全局 big_array[1L<<24] 为 16MiB，huge_array[1L<<31] 为 2GiB，位于静态存储区域；局部 int local 位于栈；main、useless 的机器指令位于代码段。小块 malloc(256) 通常来自传统堆，大块 256MiB、4GiB 分配在课件样例中来自较高地址的映射区域。

课件打印的 main 地址约 0x40060c，小块分配约 0x8359d010，大块约 0x7f...，局部变量约 0x7ffe...。这些数用于比较区域与相对布局；实际地址还受链接方式、分配器和地址随机化影响。

递归函数每次调用都产生栈帧。若每层局部数组很大，递归深度尚不大也可能用尽栈；“程序仍有足够堆空间”不能替代栈容量的判断。

8. 课堂例题：echo 的 24 字节栈帧

第 21—27 页。 源程序只有 char buf[4]，汇编却执行 subq $24,%rsp。buf 从新栈顶开始，返回地址在 buf 起点加 24 处，中间有 20 字节未用空间。

输入 23 个可见字符，再补 1 字节 \0，占偏移 0—23，虽然已经超过 buf 的语言边界，但这一具体布局下未改到返回地址。输入 24 个字符时，终止符写到偏移 24，恰好覆盖返回地址最低字节。

课件返回地址为 0x4006f6，小端内存为 f6 06 40 00 00 00 00 00。最低字节被零覆盖后变为 0x400600，返回时跳到非预期位置并崩溃。解释边界时还必须计入库函数自动补的终止符。

这也解释为什么“输入很长却暂时没有崩溃”不足以判断程序的访问是否在数组范围内：是否越界取决于对象范围，是否立即崩溃取决于被覆盖的位置。

8.1. 金丝雀的设置与检查（第 44—47 页）

函数入口从 %fs:0x28 读入进程提供的保护值，保存到栈帧；函数返回前取出，与原值比较。课件用异或比较，相同得零并进入正常返回分支，否则调用 __stack_chk_fail。

保护值位于缓冲区与关键控制信息之间，连续向上覆盖时会先改变它。地址随机化改变目标地址可预测性，栈不可执行改变能否把栈中数据当指令执行；三种机制针对的阶段不同。

9. 课堂例题：从现有指令字节读出 gadget

第 49—53 页，课件本地演示程序。 ab_plus_c 中尾部字节 48 8d 04 17 c3 从地址 0x4004d4 开始可译为求 %rdi+%rdx 到 %rax 后返回。

另一个函数用 movl $0xc78948d4,(%rdi) 存立即数，但从其内部地址 0x4004dc 开始，字节 48 89 c7 c3 又可译为 movq %rax,%rdi; ret。x86 指令长度可变，从不同字节边界开始解码会得到不同指令序列。

按顺序经过这两个片段，第一段计算和到 rax，第二段复制到 rdi，合成效果为 rdi=rdi+rdx。每个 ret 从栈顶读取下一段地址并使栈指针增加 8；课件以此说明复用既有代码的控制流与直接执行栈中注入代码的区别。

课件历史案例包括早期网络蠕虫利用输入处理漏洞传播，以及即时通信软件竞争中的协议与内存错误。其共同技术线索是：输入数据经过内存写入后，能否改变随后执行所依赖的状态。

10. 补充例：对象寿命与字符串容量

int *bad(void) {
    int value = 7;
    return &value; // The local object's lifetime ends on return.
}

返回时把地址复制到 RAX 并不会延长 value 的寿命。即使下一次读取碰巧仍看到 7，该地址也已不再指向一个存活的局部对象；后续函数可以复用该栈槽。若调用者需要结果，可直接返回整数，或由调用者提供存储位置再传入指针。

char s[4]="abc" 的四个字节依次为 a、b、c、零。strlen(s)=3，sizeof(s)=4。容量需要包含结束符；字符数、字节数和数组容量是三个问题。UTF-8 字符可能占多个字节，strlen 统计的是结束符前的字节数。
